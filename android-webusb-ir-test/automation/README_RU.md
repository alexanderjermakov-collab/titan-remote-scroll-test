# Android WebUSB IR Blaster — Windows ADB Test Harness 1.0

Комплект для Xiaomi 15T, уже сопряжённого с Windows через Wireless ADB. Приложение PoC и USB-протокол не изменяются. Автоматизация использует ADB для экрана и системной диагностики, штатный Chrome DevTools socket через временный локальный ADB forward — для чтения событий существующей страницы. Установка APK, браузерных расширений и изменение настроек безопасности отсутствуют.

**Статус:** 21 автономная программная проверка пройдена в PowerShell 7.6.9 на Linux. Реальный Windows + Xiaomi 15T Smoke Test не выполнен из среды разработки. Успех ADB, USB или ИК-приёма не заявляется. Испытания Suite начинаются только после успешных SMOKE-ADB, SMOKE-CHROME и SMOKE-UI в том же запуске.

## Состав комплекта

- `Run-WebUsbTests.ps1` — Smoke / Suite, операторские окна и отчёты.
- `WebUsbHarness.psm1` — ADB, UI XML, скриншоты, Logcat, Chrome CDP, экспорт и проверка доказательств.
- `Test-Harness.ps1` — автономные регрессионные проверки, без телефона и ADB.
- `verification.txt` — фактический результат программных проверок.
- `.gitignore` — исключение локальных результатов и идентификатора телефона из git.

Нужен **PowerShell 7.2 или новее на Windows** (`pwsh`), не Windows PowerShell 5.1. Также нужны официальные Android SDK Platform-Tools с `adb.exe` в PATH либо параметр `-AdbPath`. Дополнительных PowerShell-модулей и Node/Python на Windows не требуется.

## Первый запуск — только Smoke

Распакуйте ZIP в отдельный каталог и откройте PowerShell в нём. Смартфон должен быть уже сопряжён с этим Windows-компьютером, доступен в сети, разблокирован; Chrome — с завершённой первоначальной настройкой. Скрипт не снимает блокировку и не меняет системные настройки. Бластер для Smoke не требуется.

```powershell
pwsh -NoProfile -File .\Run-WebUsbTests.ps1 -Mode Smoke
```

Если ADB не в PATH:

```powershell
pwsh -NoProfile -File .\Run-WebUsbTests.ps1 -Mode Smoke -AdbPath 'C:\Android\platform-tools\adb.exe'
```

Smoke выполняет:

1. Проверку ADB, поиск именно Xiaomi 15T, сверку постоянного серийного номера.
2. Запуск уникального URL PoC в Chrome с `adbRun=<id>`.
3. Проверку точного URL, HTTPS, версии PoC 1.0.0 и доступности WebUSB через Chrome CDP.
4. Поиск кнопки «Очистить журнал» в UI XML, прокрутку и нажатие через `adb shell input tap`. Успех подтверждает новое событие `log cleared`, а не факт выполнения tap.
5. Скачивание штатного JSON кнопкой страницы, обнаружение нового файла в `/sdcard/Download`, копирование на Windows и сравнение событий с CDP-снимком.
6. Сохранение скриншотов, UI XML, ADB-команд, Logcat и отчёта.

Код выхода 0 означает PASS всех тестов выбранного автоматизированного режима; 1 — FAIL/BLOCKED хотя бы одной обязательной проверки. В Smoke USB/ИК-проверки отмечены BLOCKED с причиной «Not requested in Smoke mode», а не PASS.

## После успешного Smoke — Suite

Подключите бластер к телефону через OTG и выполните:

```powershell
pwsh -NoProfile -File .\Run-WebUsbTests.ps1 -Mode Suite
```

В начале Suite Smoke повторяется автоматически. Нет параметра обхода Smoke. При его ошибке USB-подключение и ИК-сценарии не выполняются. При ошибке ИК-сценария следующие зависимые проверки блокируются; первичная диагностика сохраняется.

Оператор участвует только в ИК-окнах: подтверждает готовность Enter и нажимает/удерживает физическую кнопку пульта по команде в консоли. Нажимать кнопки страницы на смартфоне не требуется в поддержанном UI-профиле.

| Тест | Условие PASS |
|---|---|
| SMOKE-ADB | Один подходящий Wireless ADB target; модель/производитель/постоянный serial проверены; `get-state=device` |
| SMOKE-CHROME | Точная вкладка данного запуска, secure context, navigator.usb и поддержанный JSON-адаптер |
| SMOKE-UI | ADB-нажатие вызвало новое `log cleared` |
| USB-CONNECT | В журнале есть VID/PID 045C:0195, open, configuration, claim, выбранные дескрипторы, FC/FE со status=ok и bytesWritten=4; после FB требуется успешный FA |
| IR-SINGLE | После команды оператору — ровно один полный FE с непустым payload и соответствующей длиной; есть подтверждение сырыми RX |
| IR-REPEATED-10 | Десять окон по одному нажатию; в каждом ровно один новый полный FE; номера seq различны |
| IR-CONTINUOUS | Не менее 11 записей в одном сеансе без повторного подключения, один `reader start`, успешное перевзведение FE после каждой записи |
| IR-HOLD | В отдельном окне удержания около 2 с получены минимум две полные записи; без декодирования повторного ИК-кода |
| USB-SESSION-RECONNECT-3 | Три close/open-сеанса через UI, новый generation и ровно один reader в каждом; после каждого — новый ИК-захват; нет операций старого сеанса после закрытия |
| JSON-EXPORT | Создан новый штатный скачанный JSON именно данного запуска; все события контрольного снимка сохранены без изменения |
| USB-PHYSICAL-RECONNECT | BLOCKED: требуется управляемый USB-хаб; программное закрытие сеанса не доказывает физическое извлечение/повторную USB-enumeration |

Контроль задержки перевзведения имеет нижний допуск 45 мс для номинальных 60 мс. Верхний предел не задан: Android может задерживать JavaScript. Это проверка порядка и факта перевзведения, а не измерение real-time характеристик.

## Смена Wireless ADB-порта и выбор устройства

Начальный адрес: `172.25.65.11:35653`. Затем используются текущие подключённые Wireless ADB transports и объявления `_adb-tls-connect._tcp` из `adb mdns services`. Порты `_adb-tls-pairing` не используются. Подсети не сканируются, ADB server не перезапускается принудительно.

После первого успешного выбора `device-state.json` сохраняет постоянный аппаратный serial. При смене TCP-порта новый target сверяется с ним. Два transport-адреса одного serial считаются одним телефоном; два разных подходящих телефона без сохранённого serial — неоднозначность и остановка без действий с экраном.

Если локальная сеть блокирует mDNS и старое соединение отсутствует, автоматически узнать новый endpoint невозможно. Тогда можно передать актуальный endpoint явно; повторное сопряжение скрипт не выполняет:

```powershell
pwsh -NoProfile -File .\Run-WebUsbTests.ps1 -Mode Smoke -Address '172.25.65.11:НОВЫЙ_ПОРТ'
```

Если подключено несколько Xiaomi 15T, задайте нужный постоянный серийный номер через `-HardwareSerial`. Скрипт читает идентификационные свойства подключённых/обнаруженных сопряжённых устройств, но экранные действия выполняет только на выбранном телефоне с явным `adb -s`.

## USB-диалоги и UI-профили

Поиск элементов основан на `uiautomator dump`: text/content-desc, package, enabled и bounds. Координаты вычисляются из текущего XML. Масштаб экрана не зашит. Неизвестный диалог не закрывается случайными координатами и не считается успешным подключением.

Поддержаны русские тексты страницы и основные кнопки USB-диалогов Chrome/Android на русском, английском и словацком. Автоматически подтверждается только обычный доступ к USB, вызванный кнопкой подключения. Галочки постоянного доступа не включаются.

Если имя устройства в Chrome отличается от IR Blaster / Smart IR, укажите его точный шаблон из сохранённого UI XML, например:

```powershell
pwsh -NoProfile -File .\Run-WebUsbTests.ps1 -Mode Suite -UsbDeviceLabelPattern '^ФАКТИЧЕСКОЕ ИМЯ УСТРОЙСТВА$'
```

Нативный UI HyperOS/Chrome пока не проверен на данном Xiaomi. При неизвестной разметке, нескольких USB-интерфейсах с требованием выбора, закрывающем экран диалоге или корпоративном запрете ADB input тест останавливается с артефактами. Это ограничение автоматизации; настройки безопасности не изменяются. Полученный XML позволит уточнить профиль скрипта без изменения USB-протокола.

## Артефакты и доказательства

Каждый запуск создаёт новый каталог `results/<UTC-id>/`:

- `report.json` и `report.md`: PASS / FAIL / BLOCKED по каждой проверке, причины и ссылки-имена доказательств;
- `device.json`, `mdns.txt`, `adb.jsonl`;
- PNG-скриншоты контрольных точек и ошибки; XML экранов;
- `logcat.txt`, `logcat-stderr.txt`, `dumpsys-usb.txt`, `dumpsys-power.txt`, `dumpsys-activity.txt`;
- JSON-снимки приложения перед/после каждого нажатия, удержания и переподключения;
- `downloaded-app-log.json`: штатный экспорт страницы, если скачивание удалось.

Проверяется длина FE по заголовку LH/LL, payloadBytes, actualBytes и числу HEX-байтов. Каждая FE-запись должна иметь собственное неиспользованное ранее подтверждение в сыром RX-потоке того же generation. Счётчик экрана, запущенная TX-операция, пустой FE или копия события парсера без RX не являются доказательствами ИК-приёма. Любое вытеснение журнала, исключение USB, stall/babble, timeout незавершённого FE или переполнение запрещает PASS соответствующего сеанса.

Скрипты не отправляют результаты на GitHub или другой сервер. На телефон не устанавливается APK. Отладочный ADB forward удаляется в finally, Logcat-процесс данного запуска завершается, тестовый USB-сеанс по возможности закрывается штатной кнопкой. Системный Logcat не очищается. Chrome и глобальный ADB server принудительно не останавливаются. Нормальный повторный запуск использует сохранённый serial, новую вкладку и новый каталог результатов.

## Известные ограничения и границы вывода

- Этот комплект ещё не прошёл реальный Windows/Xiaomi Smoke. PASS программных регрессий не является PASS аппаратного теста.
- Первичное сопряжение Wireless ADB, доступность сети и разблокировка телефона — исходные условия. Скрипт не обходит защиту Android, Chrome или PowerShell.
- CDP требует доступного штатного `chrome_devtools_remote`. При его отсутствии — FAIL Smoke без изменения настроек. Читаются глобальные переменные PoC 1.0.0; при новой версии нужен адаптер, а не молчаливое продолжение.
- Поддерживаются Download-каталог Android и штатный JSON-экспорт. Иной путь или неподдержанный диалог скачивания даёт FAIL экспорта.
- Нажатия пульта подтверждаются только косвенно, по времени и RX. Автоматически проверить сам физический факт нажатия без дополнительного оборудования нельзя.
- Физическое переподключение не автоматизировано без управляемого USB-хаба. Поэтому `hardwareAcceptanceConfirmed=false` и `physicalReconnectConfirmed=false` остаются в отчёте даже при PASS всего доступного автоматизированного объёма.
- Наличие двух FE при удержании не означает распознавание repeat-кода: декодеров нет.
- Завершение процесса извне/потеря питания может не выполнить finally; нормальный запуск и обычные ошибки очищают свои ресурсы.

## Автономные проверки самого комплекта

```powershell
pwsh -NoProfile -File .\Test-Harness.ps1
```

Проверены синтаксис всех PS-файлов, импорт модуля, нативный запуск/ошибка/тайм-аут, динамическое обнаружение TLS-connect, привязка к serial и отказ при неоднозначности, отсутствие доказательств/короткий TX/условный FA/вытеснения/старый generation/ошибки USB, сборка FE из фрагментов RX, неверная длина, повторное использование RX, пустой FE, а также создание отчёта при провале Smoke с блокировкой USB-тестов.

Справочные источники: [ADB](https://developer.android.com/tools/adb), [архитектура Wireless ADB и mDNS](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/adb_wifi.md). Pairing и connect — разные сервисы; mDNS требует поддержки сети.
