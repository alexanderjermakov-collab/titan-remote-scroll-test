ADB 1.0.41 / Platform-Tools 37.0.1. Устройств нет, mDNS-сервисов нет, connect возвращает **Network is unreachable**.

Затем новый `Run-ProtocolCheck.ps1 -Mode Smoke` реально запущен в PowerShell с этим ADB. Он отказал при нуле подходящих устройств, не выполнил экранных/USB-действий, сохранил отчёт и код выхода 1. ## Повторное испытание на Windows

PowerShell 7.2+ и уже сопряжённый Wireless ADB. Сначала из каталога automation:

```powershell
pwsh -NoProfile -File .\Run-ProtocolCheck.ps1 -Mode Smoke
```

После PASS:

```powershell
pwsh -NoProfile -File .\Run-ProtocolCheck.ps1 -Mode Protocol
```

Protocol повторяет Smoke, проверяет FC и TX, запрашивает физические нажатия для single/10 repeats/hold/трёх software reopen. Если при нажатиях воспроизведена ошибка, сохраняет FAIL исходного окна, программно переподключается и требует новый raw-backed FE. Только реальная прежняя phase=quarantine и последующий capture позволяют установить `recoveryAfterAssemblyErrorConfirmed=true`. При отсутствии воспроизведённой ошибки этот критерий BLOCKED; лабораторный mock его не заменяет. После неудачи 10/10 общий PASS не выставляется.

Поле `hardwareAcceptanceConfirmed` остаётся false, пока все обязательные реальные проверки не пройдены. Физическое USB-извлечение не подменяется close/open и отдельно не заявляется.
