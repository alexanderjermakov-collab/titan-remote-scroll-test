# Android WebUSB IR Blaster Test (PoC) 1.0.0

[Открыть тест](https://alexanderjermakov-collab.github.io/titan-remote-scroll-test/android-webusb-ir-test/)

Приложение — один автономный `index.html` со встроенными CSS и JavaScript. Внешние скрипты, APK, CDN, серверный USB-мост и декодеры ИК отсутствуют. Все USB-данные обрабатываются в браузере; журнал скачивается пользователем в JSON.

Основание: `Android_Chrome_WebUSB_Test_TZ_RU.md`, версия 1.0 от 25.10.2026. Источник параметров USB: `SmartUsbDongleManager.kt` репозитория `alexanderjermakov-collab/IR-Receiver`, снимок `da7fc5b7ea58b685b42b0101cab923f3134b0a69`. Репозиторий IR-Receiver не изменён.

## Испытание на Android

1. Откройте ссылку в отдельной вкладке **Google Chrome на Android**, через HTTPS. Не используйте встроенный браузер мессенджера. Держите экран включённым, вкладку активной.
2. Заполните поле окружения: модель телефона, Android, полная версия Chrome, адаптер/кабель. User-agent может содержать сокращённые данные.
3. Подключите USB IR Blaster через исправный OTG-адаптер с передачей данных. Закройте другие приложения, использующие бластер.
4. Нажмите **Подключить USB IR Blaster**. Выберите VID/PID `045C:0195`, подтвердите разрешения Chrome и Android. Если вариантов интерфейса несколько, выберите один. Предпочтительный класс `02/02/01` помечен звездой.
5. Проверьте этапы open / configuration / claim / RX. Для каждой команды в журнале должен быть результат `status: ok`, `bytesWritten: 4`. Автоматически: FC через 250 мс после USB-ready; FE через 900 мс независимо от identify; FA после полного FB, максимум один автоматический FA на попытку FC.
6. Направьте работающий ИК-пульт на бластер. Сделайте 10 одиночных нажатий с интервалом не менее 1 с. Ожидаются 10 полных FE-записей. Затем отдельно удерживайте кнопку около 2 с; дополнительные записи учитывайте отдельно.
7. После полного FE приложение отправляет следующий FE через 60 мс. Успешная отправка команды сама по себе не доказывает готовность оборудования.
8. Трижды отключите/подключите бластер, каждый раз явно нажимая «Подключить», и повторите захват. Перезагрузка страницы или телефона не должна требоваться.
9. Нажмите **Скачать журнал JSON**. Сохраните исходный журнал при любой ошибке. Не очищайте его до экспорта. Очистка сохраняет USB-соединение, но удаляет предыдущие события.

## Диагностика

- Нет navigator.usb / secure context: USB-действия отключены, это не доказательство неисправности бластера.
- Устройство не выбрано / отменён диалог: отдельный статус. Повторение только по кнопке.
- Ошибки open / configuration / claim / alternate / transferIn / transferOut содержат этап, имя и исходный текст исключения.
- При TX проверяются статус и полная запись четырёх байтов. Автоповторов, reset, clearHalt и скрытого reconnect нет.
- Через 3 с без FB — «Ответ identify не получен»; единственный reader продолжает ждать. Отсутствие RX до нажатия пульта нормально.
- Незавершённый FE: через 2 с без прогресса предупреждение, через 10 с сборка блокируется; сырые данные сохраняются. Отключите и подключите сеанс. Новый FE поверх незавершённой записи не отправляется.
- Физическое отключение или кнопка отключения запрещает новые TX и таймеры. `USBDevice.close()` отменяет незавершённые операции и освобождает интерфейсы. Необязательный FD опущен, чтобы не задерживать закрытие. Завершения старого сеанса не влияют на новый.

## Формат и пределы

USB Bulk IN: один незавершённый `transferIn(endpointNumber, 16384)`. Учитываются `DataView.byteOffset` и `byteLength`. Нулевое чтение не считается кадром и вызывает паузу 100 мс. Endpoint выбирается из дескрипторов, не из полного адреса USB.

Парсер собирает FA/FB по 6 байтов, FE — 6 байтов заголовка и `LH*256+LL` байтов payload. Маркеры внутри объявленного payload не интерпретируются. Обрабатываются разрывы заголовков, несколько сообщений в чтении и неизвестные байты. Сырые RX регистрируются до разбора.

Максимум RX-сборки 256 КиБ; payload 65535 байтов; журнал 5 МиБ по компактному UTF-8 представлению событий. Счётчик вытеснений виден на странице и в экспорте. Для приёмочного прогона он должен быть 0. Размер скачанного JSON с отступами и метаданными может превышать 5 МиБ.

JSON содержит время UTC и монотонное время хоста, seq, connectionGeneration, этап и операцию, направление, endpoint, запрошенные/фактические размеры, status/bytesWritten, полные HEX, исключения, окружение, ручные заметки и дескрипторы сеансов. Серийный номер не запрашивается и не экспортируется.

## Доступные проверки

До публикации выполнен `node test-poc.cjs` с детерминированной имитацией USB и времени:

- синтаксис и исполнение JavaScript;
- разрывы сообщений во всех позициях тестового кадра, объединённые FA/FB/FE;
- неизвестные байты, маркеры внутри payload, нулевая и максимальная длина 65535;
- предупреждение 2 с и блокировка 10 с;
- выбор configurationValue=7 (не зашитая 1), interface=3, endpoint IN=1 / OUT=2;
- reader до FC, задержки 250/900 мс, только один автоматический FA, перевзведение 60 мс;
- корректное чтение DataView со смещением;
- неуспешные TX/RX без скрытых повторов, закрытие pending reader и явное переподключение;
- лимит журнала, счётчик вытеснений и очистка.

После публикации облачный Chrome открыл HTTPS-страницу: isSecureContext=true, navigator.usb доступен, интерфейс инициализировался, кнопка экспорта создала скачивание JSON. Это проверка настольного Chrome, не Android. В журнале консоли не обнаружено ошибок страницы; присутствовали посторонние ошибки расширения браузерной среды.

Локальный Playwright-запуск заблокирован отсутствием Chromium: установка браузера вернула повреждённый архив. Это ограничение среды проверки, а не приложения. Имитационные проверки не заменяют Chrome Android с реальным USB-устройством.

## Приёмочные критерии

| ID | Критерий | Статус до аппаратного испытания |
|---|---|---|
| S1 | HTTPS в Chrome Android без установок | Требуется подтверждение на телефоне; HTTPS-публикация проверяется отдельно |
| S2 | Выбор VID/PID | Не подтверждён |
| S3 | open / configuration / claim / alternate | Не подтверждён |
| S4 | FC/FE и условный FA: ok, 4 байта | Логика проверена mock; аппаратура не проверена |
| S5 | Узнаваемый identify и/или полный FE | Не подтверждён |
| S6 | Полный FE после ИК-воздействия | Не подтверждён |
| S7 | 10 раздельных записей без reconnect | Не подтверждён |
| S8 | Три повторных подключения | Логика проверена mock; аппаратура не проверена |
| S9 | Экспорт восстанавливает порядок и данные | Формирование реализовано; проверить реальный скачанный журнал |

**Аппаратная совместимость остаётся неподтверждённой до испытания с реальным USB IR Blaster.** Успешный claim/TX без RX подтверждает только часть пути. Один полный FE после нажатия подтверждает приём ИК; для приёмки нужны все S1–S9.

## Известные ограничения

- Только активная вкладка Chrome; фон, блокировка экрана и длительная промышленная эксплуатация не проверены.
- Нет WebUSB force-claim, в отличие от исходного Android-кода. Драйвер/политика браузера может запретить доступ к конкретному интерфейсу.
- X/Y в FA/FB сохраняются без неподтверждённой трактовки версии.
- Задержки повторяют исходное приложение; они не доказаны как ограничения прошивки. Слепые интервалы между захватами не измерены.
- Страница не определяет автоматически, какому физическому нажатию соответствует FE; 10/10 сверяет испытатель.
- Журнал хранится в оперативной памяти до экспорта; перезагрузка страницы его удаляет.
- Android-диалоги разрешений, реальная USB-совместимость и сохранение JSON в Chrome Android требуют аппаратной проверки.
- Ошибка на одном смартфоне или отсутствие ответа не означает невозможность WebUSB на всём Android. Альтернативные транспорты не разработаны.
